# ADR-0003. Стек бекенду

**Статус:** Запропоновано
**Дата:** 2026-10-29
**Джерела:** [requirements_digest.md](../requirements_digest.md) (BR-1, BR-4, BR-10, BR-15, BR-17, TA-5, TA-9, TA-13, FB-11, G5); [3.5](../../results/3.5_acceptance_criteria_result.md) (SYS-AC-06, SYS-AC-09, US-5.1-AC-05, Q01, Q11); пов'язані ADR-0001, ADR-0004, ADR-0005, ADR-0006.

## Контекст

- Сервер — єдине джерело істини для дедлайнів, поточного часу, статусів і ролей (TA-5, FB-10, FB-11).
- Бронювання атомарне (BR-1), підтвердження за токеном кімнати перевіряє вікно часу (BR-4) і ідемпотентне (BR-10, US-5.1-AC-05), ідентифікатор власника береться із сесії (BR-17).
- Обсяг даних демонстраційний (TA-13), навантаження мінімальне.
- Над сервером працюють троє людей; одна з них (Вікторія) також пише клієнт, тому однакова мова з клієнтом важлива.

## Критерії

1. Низький поріг входу й підтримка ШІ-асистентом.
2. Одна мова з клієнтом (TypeScript, ADR-0002).
3. Мінімум налаштувань і інфраструктури.
4. Поділ на модулі без конфліктів.

## Розглянуті варіанти

- **A. Node.js + Express + TypeScript**, валідація вводу через Zod.
- **B. Node.js + NestJS + TypeScript.**
- **C. Python + FastAPI.**

| Критерій | A. Express | B. NestJS | C. FastAPI |
| --- | --- | --- | --- |
| Поріг входу, ШІ | Мінімальний API, найбільше прикладів | Декоратори, модулі, DI: багато понять на старті | Простий, багато прикладів |
| Одна мова з клієнтом | Так, спільні схеми в `shared/` | Так | Ні: друга мова й дублювання схем |
| Налаштування | Кілька залежностей | Генератор проєкту, багато шаблонного коду | Окреме віртуальне середовище, другий менеджер пакетів |
| Поділ роботи | Роутер на модуль | Модуль Nest на модуль | Роутер на модуль |

## Рішення

**Варіант A: Node.js (LTS) + Express + TypeScript** **[Пропозиція]** у `server/`. Мажорна версія Node.js — поточна LTS (22 або 24), Express — 5 **[Потребує перевірки]**. Під час розробки TypeScript запускається без окремої збірки (наприклад, через `tsx`).

- **Стиль API:** REST поверх JSON з префіксом `/api`, один процес для API й фонового завдання (ADR-0006). Перелік ресурсів і коди статусів — у 4.3.
- **Валідація вводу:** схеми Zod у `shared/`, ті самі на клієнті й сервері; сервер валідує завжди, клієнт — для зручності (TA-14).
- **Структура:** модулі за доменом (автентифікація, кімнати, слоти, бронювання, адміністрування); у кожному — роутер, сервіс із бізнес-правилами й доступ до даних через ORM (ADR-0004). Бізнес-правила живуть у сервісах, а не в роутерах, щоб їх можна було тестувати без HTTP (ADR-0008).
- **Як забезпечуються правила:**
  - BR-1 — обмеженням унікальності в сховищі; сервіс перетворює порушення обмеження на помилку «слот зайнятий» (ADR-0004, US-3.4).
  - BR-4, BR-10 — підтвердження виконується одним умовним оновленням за статусом і часом; повтор для вже підтвердженого повертає успіх без змін (ADR-0006).
  - BR-15, BR-17 — проміжні обробники автентифікації й ролі; ідентифікатор користувача й роль беруться із сесії (ADR-0005).
  - TA-5 — поточний момент береться з єдиного джерела часу на сервері, яке в тестах підміняється (ADR-0008); серверний час додається у відповіді з бронюваннями.
  - G5, TA-9 — помилки повертаються в єдиному форматі з машинним кодом причини (4.3).

## Наслідки

- Простіше: одна мова, спільні схеми, один процес; Express знайомий ШІ-асистенту, тому кодогенерація передбачувана.
- Складніше: Express не задає структуру, тому правила структури модулів треба записати у файл інструкцій для ШІ (крок AI-Harness), інакше код розповзеться.
- Ризик: межові правила часу (Q01: включність меж вікна, визначальний момент) ще не визначені; вони ізолюються в одній функції перевірки вікна, щоб відповідь команди змінювала лише її.
- Для 4.3: REST, JSON, префікс `/api`, єдиний формат помилок із машинним кодом.
- Для 4.4: `GET /api/health` повертає 200 і стан підключення до бази.
- Стосується: Валентини, Олександри, Вікторії.

## Що відхилено

- **B. NestJS** — багато понять і шаблонного коду для 5 тижнів, вигода від DI на такому обсязі мала.
- **C. FastAPI** — друга мова в проєкті й дублювання схем валідації між клієнтом і сервером.
