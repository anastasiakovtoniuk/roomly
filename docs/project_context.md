# Контекст проєкту Roomly

## Продукт

**Roomly** — мобільний застосунок для пошуку та бронювання навчальних кімнат для групової роботи (study rooms) в університетських бібліотеках або на території кампусу.

Продукт розрахований на університети, де такі кімнати вже існують і студенти бронюють їх на конкретний часовий слот.

## Проблема (гіпотеза, не підтверджена)

Студентська група бронює кімнату, але через зміну планів не приходить і не скасовує бронювання. Кімната показується зайнятою, хоча вона порожня, тож інші студенти не можуть нею скористатися. Адміністрація не має зручного способу перевірити, чи справді кімната використовується.

## Запланований функціонал

- перегляд кімнат: місткість, розташування, обладнання;
- вибір дати та вільного часового слоту;
- створення та скасування бронювання;
- історія бронювань;
- нагадування про майбутнє бронювання;
- підтвердження присутності через QR-код у кімнаті.

## Ключова механіка: підтвердження присутності

- Після початку бронювання діє **grace period**. Його налаштовує адміністратор, орієнтовно 5–15 хв.
- За цей час **будь-хто з групи** сканує QR-код у кімнаті.
- Якщо присутність не підтверджено, бронювання **автоматично скасовується**, а кімната знову стає доступною.

## Ролі

- **Студент (користувач)** — шукає кімнати, бронює їх, скасовує бронювання й підтверджує присутність.
- **Адміністратор** — працівник бібліотеки або кампусу. Керує кімнатами, слотами, QR-кодами, бронюваннями та обліковими записами студентів.

## Обмеження команди

- Команда з 5 студентів: PM / Frontend, 2× Backend, Frontend / UI/UX, Backend / DevOps.
- MVP має бути закодований і продемонстрований наживо до кінця курсу.
- Великі можливості на зразок оплати, чату чи інтеграції з університетським розкладом не входять у базову концепцію.
