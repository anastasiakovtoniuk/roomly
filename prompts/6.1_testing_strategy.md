# 6.1 Тестова стратегія

Промпт, за яким ШІ аналізував архітектуру проєкту й складав `docs/testing-strategy.md`, і результат аналізу. Issue #47, авторка — Дерменжи Валентина; асистент — Claude Code.

## Промпт

**Промпт** (структурований, Claude Code; гілка `docs/47-testing-strategy` від `origin/feature/checkin-admin`, PR — у `feature/checkin-admin`):

- **Завдання:** скласти `docs/testing-strategy.md` для Roomly на 1–2 сторінки, конкретно, без загальної теорії. Документ українською, коміти й опис PR англійською. Код, ADR і контракти не змінювати; у README — лише посилання на стратегію (остаточний текст про команди робить #55).
- **Що прочитати (не вгадувати):** ADR-0001, 0003, 0006, 0008 (усі «Запропоновано» — не видавати за затверджені); `docs/scenarios/checkin_admin_flow.md` (рішення: Q01 вирішено, Q03/Q18 — ні); `server/vitest.config.ts`, `server/test/globalSetup.ts`, `server/test/helpers/{factories,auth,time}.ts`, `server/test/*.test.ts` (як насправді виглядають тести, `setClock`, ізоляція даних); кореневий `package.json`; `.github/workflows/ci.yml`; AC і SYS-AC у `docs/requirements.md` §4.
- **Розділи документа:**
  1. **Межі.** Автотести: статуси й переходи (SYS-AC-02…07, 10), конкурентність (SYS-AC-06, 07), ролі й чужі дані (SYS-AC-09, BR-8), валідація, коди помилок, чиста клієнтська логіка (відлік, стан екрана check-in, мережеві помилки). Вручну: верстка, камера й QR на iOS Safari / Android Chrome, друк і читання QR з паперу, реальний таймер, доступність на телефоні, US-A.5-AC-03.
  2. **Інструменти й рівні.** Інтеграційні API-тести (Supertest + реальна SQLite) — основний рівень; unit для чистих функцій; компонентні тести клієнта лише з логікою стану (після #48); без E2E; Prisma й БД не мокаємо, мокаємо лише час.
  3. **Організація.** Розташування файлів (`server/test/*.test.ts`, `*.ac.test.ts`, `server/test/helpers/`, клієнтські тести), іменування від ID критерію, `npm test` з кореня.
  4. **Дані й ізоляція** — так, як у коді: `test.db` з міграцій у `globalSetup.ts`, унікальні дані, без очищення, `resetClock()`, планувальник не стартує, конкурентність через `Promise.all`.
  5. **Правила для тестів ШІ:** з AC/Gherkin, не з коду; успіх і помилка/межа для кожного критерію; відкриті Q/G не фіксувати (Q03/Q18); «зламай код навмисно»; без `toBeDefined`, `status < 500` і зайвих моків.
  6. **Що не покривається** (відкриті питання й чому).
- **Правила:** кожне твердження про файл чи команду підтверджувати наявним файлом (`rg --files server/test`); суперечності між джерелами показувати, а не вибирати мовчки; не вигадувати інструментів, папок і команд.
- **Відомі розбіжності, які перевірити:** issue каже, що клієнтська логіка «тимчасово тестується в `server/test/client*.test.ts`», а в репозиторії є `client/vitest.config.ts` (#48) — описати фактичний стан; ADR-0008 «Запропоновано»; звірити список тестових файлів, `*.ac.test.ts` позначити запланованими, якщо їх немає (#50).
- **Завершення:** `npm run format:check`, `npm run lint` з фактичним результатом; підсумок: що покрито, що відкрито, які розбіжності між ADR і кодом.

## Результат

**Що встановив аналіз** (кожен пункт перевірено файлом):

- Тестові файли сервера: 15 у `server/test/`, серед них уже є `admin.ac.test.ts` (#51). Отже, твердження промпту «`*.ac.test.ts` ще не існують» застаріло: заплановані лише набори #50.
- `server/test/client*.test.ts` немає. Клієнтські тести (16 файлів) лежать у `client/src/**`, запускаються `client/vitest.config.ts` (середовище `node`, jsdom за рядком-директивою) і входять у кореневий `npm test` через `--workspaces --if-present`.
- На сервері немає моків Prisma; підміни — лише час (`setClock`/`useClock`), фальшивий `setInterval` і `console.error` у тесті планувальника. На клієнті мокаються `fetch`, `navigator.onLine`, годинник і `useAuth`.
- Планувальник автоскасування стартує лише з `server/src/index.ts`, не з `createApp()`; `fileParallelism: false` — через глобальне ліниве автоскасування на спільній базі.

**Що запропоновано:** документ із семи розділів — межі, рівні й моки, організація, дані й ізоляція, правила для ШІ-тестів, непокрите й розбіжності. Числа тестів не дублюються: вони змінюються, тож документ посилається на [testing-report.md](../docs/testing-report.md).

**Що змінено після перегляду:**

- Правило «мокаємо лише час» уточнено: воно точне для сервера, а клієнт не має сервера й мокає межі середовища.
- Рядок про Q11 переписано: тести клієнта є, відкритою лишається цільова поведінка, а не відсутність тестів.
- Додано розділ «Розбіжності»: issue проти коду (клієнтські тести), ADR-0008 проти коду (компонентні тести), дві позиції щодо US-A.5-AC-03 (`testing-report.md` #51 проти `adminBookings.test.ts` #42), `toBeDefined` у `factories.test.ts`.
