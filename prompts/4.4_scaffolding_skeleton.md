# Промпт для каркаса застосунку (Walking Skeleton) та інструкцій для ШІ

Ти — досвідчений full-stack інженер, який налаштовує репозиторій студентської команди з 5 людей. Твоє завдання: створити порожній, але живий наскрізний каркас Roomly — UI, API й база даних з'єднані й запускаються однією-двома командами — та підготувати файл інструкцій для ШІ-асистентів у корені репозиторію. **Бізнес-логіку User Stories не реалізуй**: жодних екранів бронювання, входу, роутерів кімнат чи бронювань. Історії реалізуватимуться пізніше за цим каркасом і контрактами.

## Вхідні дані

До запиту додано файли:

- `docs/adr/0001…0008` — чинні рішення команди (статус «Запропоновано» не дає права їх змінювати). Для каркаса ключові: ADR-0001 (npm workspaces `client`/`server`/`shared`, модулі за доменом), ADR-0002 (React + Vite + TypeScript, React Router, CSS Modules, проксі `/api`, одна обгортка над fetch), ADR-0003 (Express 5 + TypeScript через `tsx`, REST `/api`, `GET /api/health` з перевіркою бази, підмінюване джерело часу), ADR-0004 (SQLite + Prisma **7.10.1** з адаптером better-sqlite3, `partialIndexes` для BR-1, тільки `prisma migrate`), ADR-0005 (у каркасі автентифікації немає, лише місце для проміжних обробників), ADR-0006 (таймер автоскасування не підключати), ADR-0007 (без Docker, `npm install` + `npm run dev`, `.env` з `.env.example`, ідемпотентний seed адміністратора), ADR-0008 (Vitest + Supertest на окремій тестовій SQLite, ESLint, Prettier, CI).
- `docs/contracts/data_model.md`, `docs/contracts/api_spec.md`, `docs/contracts/error_format.md` — контракти. Схема Prisma, перелік статусів, коди помилок і формат відповіді `health` беруться звідси дослівно.
- `AGENTS.md` — чинні інструкції для ШІ, написані до появи коду; їх треба оновити за фактичним каркасом.
- `README.md` — опис продукту; до нього додається розділ запуску.

## Рішення, що діють для каркаса

- Node.js 22 LTS: на ньому ADR-0004 перевірив Prisma 7 і better-sqlite3 під Windows.
- Prisma фіксується точно на 7.10.1; тег `latest` вказує на 8.0.0-rc.
- Команда розробляє на Windows; скрипти мають бути кросплатформені, без bash-специфіки.
- Один `.env` у корені для клієнта й сервера. `.env.example` без реальних секретів; наявний `.env` не перезаписується.
- `npm run dev` застосовує лише наявні міграції (`prisma migrate deploy`) і не скидає базу.

## Завдання

### 1. Структура й конфігурація кореня

- `package.json` з workspaces і скриптами: `dev`, `build`, `test` (одноразовий, не watch), `typecheck`, `lint`, `format`, `format:check`. Назви — як в `AGENTS.md`.
- `.nvmrc` і `engines` з версією Node.js; спільний `tsconfig.base.json` зі `strict`.
- `eslint.config.js` (flat config, typescript-eslint, react-hooks, сумісність із Prettier), `.prettierrc.json`, `.prettierignore` (документацію не переформатовувати).
- `.gitignore` (`.env`, `*.db`, згенерований клієнт Prisma, `node_modules`, `dist`), `.gitattributes` з LF, щоб `format:check` не падав на Windows.
- `scripts/ensure-env.mjs` — створює `.env` з `.env.example`, якщо його немає.
- `.github/workflows/ci.yml`: `npm ci`, lint, format:check, typecheck, test, build.

### 2. `shared/`

Лише те, що вже визначено контрактами: значення статусів бронювання, ролей, результатів підтвердження, `scope` списку; константи grace period, мінімальної довжини пароля й назви cookie; усі коди помилок із HTTP-статусами й тип тіла помилки; тип відповіді `GET /api/health`. Схем Zod для історій ще не додавати.

### 3. `server/`

- `prisma/schema.prisma` за `data_model.md`: 5 моделей, усі поля, зв'язки з `onDelete: Restrict`, унікальні обмеження, індекси, частковий унікальний індекс BR-1 через `partialIndexes`. Перша міграція через `prisma migrate dev`; перевір, що SQL міграції містить `CREATE UNIQUE INDEX … WHERE status IN ('active', 'confirmed')`.
- `prisma.config.ts` (Prisma 7: адреса бази тут, а не в схемі). Відносний шлях SQLite рахувати від `server/`, щоб міграції, сервер і тести відкривали один файл.
- `prisma/seed.ts`: ідемпотентне створення адміністратора з `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`; без змінних — зрозуміла помилка; наявного користувача не змінювати.
- `src/app.ts` + `src/index.ts`: Express, `express.json()`, роутер `modules/health`, обробник невідомих шляхів `/api` (`ENDPOINT_NOT_FOUND`), єдиний обробник помилок (нерозбірний JSON → `VALIDATION_ERROR`, невідоме → `INTERNAL_ERROR` без стеку у відповіді).
- `GET /api/health` за `api_spec.md` §4: `SELECT 1` до бази; 200 з `database: "ok" | "unavailable"` і `serverTime`.
- `src/lib/clock.ts` — підмінюване джерело часу; `src/lib/appError.ts` — помилка з кодом із контракту.
- `test/`: Vitest + Supertest; `globalSetup` створює окрему `test.db` наявними міграціями. Тести: health (з підміненим часом), 404 у єдиному форматі, нерозбірний JSON.

### 4. `client/`

- Vite + React + TypeScript, проксі `/api` на порт сервера з кореневого `.env`.
- `src/api/http.ts` — єдина обгортка над fetch: розбирає тіло помилки в `ApiError` з кодом, окремо `NetworkError` без відповіді сервера.
- Сторінка-заглушка: назва Roomly, стан системи з `GET /api/health` (API, база, час сервера), перелік майбутніх екранів студента й адміністратора з ID історій. Mobile-first, світла й темна тема.

### 5. Інструкції для ШІ

- Онови `AGENTS.md` за фактичним каркасом: поточний стан (каркас без історій), посилання на контракти, фактична структура папок, версії, команди з їхнім реальним ефектом, змінні середовища. Правила кодогенерації, інваріанти й заборони не послаблюй.
- `CLAUDE.md` у корені лише підключає `AGENTS.md` (`@AGENTS.md`) і нагадує про контракти, щоб правила не дублювалися.

### 6. README

Розділ «Локальний запуск»: вимога до Node.js, дві команди, що робить `npm run dev`, адреси UI й `/api/health`, очікувана відповідь, інші команди, структура папок, посилання на технічну документацію.

## Правила

- Не реалізуй історій, автентифікації, сесій, Zod-схем, таймера автоскасування й демо-даних: це наступні етапи.
- Не вигадуй полів, кодів помилок, статусів і змінних середовища поза контрактами й ADR; якщо чогось бракує, назви прогалину.
- Не використовуй `prisma db push` і не дописуй SQL міграцій вручну.
- Залежності — актуальні стабільні версії, сумісні між собою (перевір peer-залежності), Prisma — точно 7.10.1.
- Не коміть `.env`, бази й згенерований клієнт Prisma.
- Не стверджуй, що щось працює, якщо команду не запускали.

## Формат відповіді

1. Дерево створених файлів.
2. Вміст кожного файлу.
3. Команди перевірки й їхній фактичний результат.
4. Що не перевірено і чому.

## Перевірка перед відповіддю

- З чистого клону `npm install` і `npm run dev` піднімають сервер і клієнт; `GET /api/health` напряму й через проксі клієнта повертає 200 з `"database": "ok"`.
- Повторний `npm run dev` не змінює `.env`, не застосовує міграцій повторно й не дублює адміністратора.
- `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm test`, `npm run build` проходять.
- Міграція містить частковий індекс BR-1.
- Невідомий шлях під `/api` повертає тіло з `error.code = "ENDPOINT_NOT_FOUND"`.
- `AGENTS.md` і README описують ті самі команди, що є в `package.json`.
